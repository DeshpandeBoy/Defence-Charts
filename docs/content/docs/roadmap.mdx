## Implemented

**A1-A3:** strict monorepo boundaries, ESM builds, token and determinism gates, `ChartPlan`, canonical
data, text fitting, six line/area rungs, and pure `planChart`.

**A2.1:** the default fitting model is now backed by a generated, content-pinned Roboto Flex
metrics table. Available-face calibration produced a `1.57` fallback safety factor, and the
planner's typography inputs and generated CSS are checked together. Windows' Segoe UI Variable
fallback remains explicitly unverified; it is not presented as measured.

**A4:** frame geometry, hook-free SVG primitives, `Chart`, accessible table output, semantic test
helpers, public API and tree-shaking gates.

**A5:** `AutoChart`, `useElementSize`, animation-frame batching, server `initialSize`, and fixed-point
containment checks in fake and real browsers.

**A6:** two-stage transitions across rung changes — axis and gridlines first, marks second — driven
entirely by CSS. No tween library and no animation hook, so `Chart` stays a server component that
ships no client JavaScript. Gridlines and ticks are keyed by domain value rather than pixel position,
which is what lets them keep their identity through a tick-count change instead of being replaced;
a replaced element cannot animate at all. Motion is opt-in at the platform level: the rules live
inside `@media (prefers-reduced-motion: no-preference)`, so an environment that expresses no
preference gets a still chart, and the still chart is the baseline rather than a degraded version of
the animated one. A measured 0.50% boundary floor showed that transitions alone could not prevent
new marks from appearing without a previous value, so `@gx/react` now keeps the last accepted size
class and applies a 1% fractional deadband. `SizeContext` and `planChart()` remain pure and
memory-free.

**B1-B3:** the presentation token tree, Rail and Neutral themes, and the typed responsive-threshold
surface are closed for the current line/area planner. Tick density, value-region height budgets,
encoding substitution, point-renderer budgets, and standalone nominal-cell conversion are all
serialisable `PlanPolicy` inputs. `PlanOverrides` remains a separate post-resolution escape hatch
for forcing a decided `ChartPlan` field. Acceptance coverage protects the distinction and the
default provenance tiers. The generated source contains 198 presentation tokens, the 30-row
granularity manifest has zero entries owed to B1 or B2, and gate G20 is part of the verification
chain. Twelve declared token candidates are reserved for later chart-family renderers; their
presence does not imply that line/area consumes them today.

Bar/column is the first breadth chart because horizontal transposition makes the responsive thesis
most visible. Donut follows because it combines reflow, reveal, and aggregation. KPI proves the
Micro end at one cell.

## Publishing blockers

1. Choose the project name and npm scope. `@gx/*` is a placeholder.
2. Complete the C grid shell before expanding chart breadth.
3. Expand chart breadth only after the line/area renderer contract is stable.
4. Finish release automation and package validation.

## Docs work still gated

StackBlitz examples start after npm publishing. A button that opens a project importing private
packages would look complete and fail for every user, so this site keeps executable examples local
until the scope is real.
