# @gx/docs

The documentation site. A [Next.js](https://nextjs.org) app on
[Fumadocs](https://fumadocs.dev), and a workspace member like any other — it consumes
`@gx/core`, `@gx/primitives`, `@gx/react` and `@gx/tokens` through `workspace:*`, so what it
demonstrates is the library as built, not a copy of it.

```bash
pnpm --filter @gx/docs dev        # http://localhost:3000
pnpm --filter @gx/docs build
pnpm --filter @gx/docs typecheck
pnpm --filter @gx/docs lint
```

`pnpm build` and `pnpm typecheck` at the root reach this package through turbo; `pnpm lint`
does not, and that is deliberate — see below.

| Path | What it is |
|---|---|
| `content/docs/` | The MDX. This is the site; everything else renders it. |
| `src/lib/source.ts` | The content-source adapter. Collections use the [Macro API](https://fumadocs.dev/docs/mdx/macro). |
| `src/lib/layout.shared.tsx` | Shared layout options. |
| `src/components/resize-lab.tsx` | Ours, not scaffold — the ladder demonstrated at the sizes it describes. |
| `src/app/(home)/` | Landing page. |
| `src/app/docs/` | Documentation layout and pages. |
| `src/app/api/search/route.ts` | Search route handler. |
| `.source/` | Generated by fumadocs-mdx from `content/`. Build input, not source. Gitignored. |

## Two places this package is deliberately not like its siblings

Both are real decisions with reasons, not drift. If either is ever changed, change it on
purpose.

### 1. It owns its ESLint config

`eslint.config.js` at the root ignores `docs/**`, with the reasoning stated there: running the
library's house rules over a fumadocs scaffold applies rules to code nobody here wrote, and the
first thing it reports is a `consistent-type-imports` complaint about generated-shaped template
code. `docs/eslint.config.mjs` and `pnpm --filter @gx/docs lint` are the run that means
something here.

### 2. It owns its `tsconfig.json` — and Next rewrites that file

`docs/tsconfig.json` does **not** extend `tsconfig.base.json`. Two consequences worth knowing
before touching it:

- **The base config's strict flags do not apply here.** `verbatimModuleSyntax`,
  `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitReturns` and
  `useUnknownInCatchVariables` are all on for `packages/*` and `apps/*` and all off for this
  directory. That is debt, not design. The reason it has not been paid is that the scaffold and
  our own code (`src/components/resize-lab.tsx`, `src/lib/`) share one config, so turning a flag
  on means fixing template code to satisfy it.
- ⚠ **Comments and hand-made choices in `docs/tsconfig.json` do not survive `next build`.**
  Next's `writeConfigurationDefaults` rewrites a tsconfig it considers its own, and it bails only
  when it sees an `extends` or `references` key — which this file has neither of. This is why
  `apps/rsc-fixture/tsconfig.json` carries an `extends` it does not strictly need, and why the
  explanation you are reading lives in this README rather than in the config itself.

  **Adding `"extends": "../../tsconfig.base.json"` is what fixes both bullets, and it is not a
  one-line change** — it turns on every flag in the first bullet at once, over scaffold code. Do
  it as its own piece of work, not as a drive-by.
