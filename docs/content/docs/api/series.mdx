title: Series and DataPoint
description: The canonical, serializable actual-value contract shared by every GX layer.
---

```ts
export type DataPoint = {
  readonly x: number | Date
  readonly y: number | null
}

export type Series = {
  readonly id: string
  readonly label?: string
  readonly unit?: string | null
  readonly target?: number | null
  readonly status?: 'positive' | 'negative' | 'neutral' | 'warning' | 'critical' | null
  readonly points: readonly DataPoint[]
}
```

## Rules

**Stable `id`:** identifies a series across plans and future transitions. Do not derive it from the
array index when the series can reorder.

**Optional `label`:** human-readable text for legends, direct labels, and tables.

**KPI metadata:** `unit`, finite `target`, and textual `status` are optional metric qualifiers.
They are rendered as visible text and in the summary table; status is not colour-only.

**Progress:** the `progress` chart type uses the latest finite `y` as current and requires a
finite positive `target` for determinate completion. It exposes `remaining` up to the target and
`over target` beyond it; missing or invalid current/target values remain explicitly indeterminate.

**Heatmap:** the `heatmap` chart type expects temporal `x` values and treats each series as a row
of activity cells. `y: null` remains an explicit missing cell. Dense temporal grids may use weekly
binning when the project-owned nominal cell floor cannot be maintained; the floor is Tier C, not a
perception claim. The HTML data table is the non-colour equivalent of the cell intensity encoding.

**`x`:** numeric or temporal. A series should not mix the two domains.

**`y: null`:** a gap, not zero. The line breaks because no reading exists. Use `0` only when the
measured value is actually zero.

## describeShape

```ts
const shape = describeShape(data)
```

The helper derives series count, point count, temporal-domain presence, negatives, and maximum label
length. It does not put actual values into `planChart`.
