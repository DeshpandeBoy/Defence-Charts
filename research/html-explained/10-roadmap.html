What still has to be completed?

Read this from top to bottom. The first group unlocks the next. “Planned” means it is in the product roadmap; it does not mean implementation has started.

C0 / contract
review, then next

Finish the grid seam

Turn the layout contract into the adapter that a real grid can use.

  • C0.1: review and promote stable WidgetId, WidgetLayout, 12-column coordinates, constraints, and snapshot versioning.
  • C0.2: map that contract to the pinned react-grid-layout@2.2.4 API without leaking the dependency into pure core code.
C1–C4 / grid
immediate build

Build the dashboard people can actually use

The grid owns outer geometry. The chart only explains its own data inside the box it receives.

  • C1: controlled 12-column layout, compaction, push-down, min/max constraints, and resize measurement.
  • C2: widget shell with header, title, actions, loading/empty/error states, and drag-from-header behavior.
  • C3: keyboard and touch behavior, focus order, visible focus, and chart-content drag cancellation.
  • C4: stable layout persistence callbacks, migration/versioning, stress tests, and real browser proof.

Prove that a stranger can consume it

The repository passing its own tests is only one part of a release.

Product analysis translated into code

What changed in the way we build?

The research was useful because it changed ownership decisions. These are the rules that keep the library understandable as it grows.

shadcn lesson

Compose the surface

Use a chart shell plus optional pieces: config, tooltip, legend, loading, empty, error, and table. The shell organizes the experience; the planner still owns the chart answer.

Basedash lesson

Give the dashboard context

Quiet card chrome, generous space, a shared filter row above the grid, drag from the header, 12px gaps/padding, and a narrow one-column policy make the page feel like a dashboard rather than a pile of charts.

ownership rule

Keep three states separate

layoutState says where a widget lives. filterState says what the user is asking. dataState says what arrived. The host app owns fetching, filters, and persistence.

coordinate rule

Each layer owns one box

Dashboard → widget → plot → overlay. The grid owns the widget box. The chart divides that box. Tooltips and crosshairs sit out of normal flow. A chart never makes the dashboard grow by surprise.

open-source boundary

Free first, Pro later

Free means core, grid, basic interactions, and standard chart families. Advanced filters, linked views, brush/zoom, and one validated Pro capability come only after the public contracts are stable.

evidence rule

Research is not runtime proof

A proposal, a screenshot, and an upstream API note help us decide. They do not prove our package works. Every claim must eventually point to code, tests, packed consumers, or real-browser evidence.

Definition of done

When can we say “this is built”?

All of these must be true for the corresponding surface. A green card in the repository is not a green release by itself.

For a chart family

  • Plan: its data meaning and size ladder are explicit.
  • Render: SVG and table/fallback output agree with the plan.
  • Explore: tooltip, legend, keyboard, touch, and reduced-motion behavior are proven.
  • Evidence: unit, browser, accessibility, visual, and performance checks pass.

For the library release

  • Install: a fresh app can use the packed artefacts, not just source files.
  • Import: public exports, CSS, ESM, RSC, Vite, peer dependencies, and tree-shaking work.
  • Operate: layout, filters, data, and persistence boundaries are documented.
  • Claim: docs describe what is shipped, what is experimental, and what is still planned.

The next exact sequence

What should happen next?

This order keeps the work small enough to review and strong enough to unlock the next step.

  1. Promote C0.1 after coordinator review.Make the Widget Layout contract the accepted source of truth. Do not add React behavior to it.
  2. Complete C0.2 with the pinned grid adapter.Keep the pure ./core and browser-facing ./react split clear, then prove one controlled 12-column layout.
  3. Build C1–C4 as one dependable dashboard seam.Placement, compaction, widget chrome, keyboard/touch access, measurement, persistence, and browser stress belong before chart expansion.
  4. Build I1 and D0 together at the contract level.Stable datum identity, tooltip/legend/accessibility contracts, and the chart-family union prevent every later family from inventing a different interaction model.
  5. Cut Preview from packed artefacts.Line/area plus the real grid must work in a fresh consumer before the project calls itself reusable.
  6. Expand through D1–D7, then publish Free v1.Each family repeats the same proof. Publication research can prepare the path, but it cannot replace runtime and consumer evidence.

In one sentence: we are not just adding charts; we are building a dependable chain from data → plan → widget box → interaction → package → consumer proof.
