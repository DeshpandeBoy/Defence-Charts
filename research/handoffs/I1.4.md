# I1.4 — Static and interactive legend

## Current state

The I1.4 implementation is complete on the isolated branch and is ready for coordinator review.
The current code checkpoint is committed together with this handoff; the commit hash is reported
by the agent after commit creation.

Implemented:

- Hook-free static Legend output for internal and external plan placements.
- Explicit absent/direct behavior: both render no legend; direct labels remain the sole identification
  surface, preventing duplicate legend content.
- Stable series order and stable Series.id/data-series-id identity.
- Plan capacity enforcement, including zero and fractional capacity handling.
- Missing and whitespace-only labels fall back to the stable series ID; duplicate display labels stay
  as separate series entries.
- External showValues/showPercent detail using the latest defined value and a deterministic
  absolute-share percentage.
- Controlled client LegendControl with aria-pressed, native button semantics, keyboard activation,
  stable hidden entries, and parent-owned visibility state.
- Tokenised legend layout, series swatches, focus styling, reduced-motion transition gating, and
  forced-colors rules. Legend nodes are absolute descendants of the measured figure and do not
  participate in normal flow.

## Known limitations and coordinator integration

- Legend and LegendControl are implemented in task-local modules, but the coordinator must decide
  and perform any public export-barrel additions after reviewing this handoff. Central exports were
  intentionally not edited in this task.

  central integration files are outside this task's allowed write set. The component accepts a full
  ChartPlan, hidden ID list, and visibility callback, so the coordinator can connect it to the
  I1.1 controlled interaction state without moving visibility ownership into the component.

  threshold. Other chart-family plans may select internal or external placements later.
- The dependency gate retains the existing no-orphans warning for packages/tokens/src/tokens.ts;
  no new dependency violation was introduced.
