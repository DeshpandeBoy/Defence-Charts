06 / Fonts + metrics

Text is geometry.

The planner must know whether a label fits before the browser paints it. That is why the project starts with one reference family and a generated advance table instead of pretending every font has the same width.

Short answer to “why are fonts limited?” A new font changes label geometry. Until its metrics are measured and carried atomically with the CSS settings, the planner can say “fits” while the browser collides labels.

What the metrics table contains

Not a font engine. A safe width model.

measureText() is intentionally simple and conservative. It is designed to make the resolver deterministic, not to reimplement browser shaping.

Known glyph advances

The generated sparse table covers the common printable set, Latin-1 characters used in labels, currency symbols, punctuation, and the arrows used by compact summaries.

Width is calculated as normalized advance × rank font size × safety factor, plus letter spacing.

Banded fallback

Unknown code points use separate fallback bands for Latin, wide CJK/full-width characters, and combining marks. One fallback number would be wrong by roughly 2× for one of those groups.

Per-rank tables

Optical sizing and weight change advances. The table is keyed by A–E rather than by one normalized size so a 10px label is not guessed from a 13px label.

Safe-direction error

The reference table can be wider than a fallback face, which leaves slack. A wider actual face is dangerous because it can collide; the safety factor is chosen to bias toward early degradation.

The calculation

How a label gets measured.

Follow this code path when investigating an overlap bug. The important detail is what the function refuses to do.

function measureText(text, rank, metrics, style = {}) {
  let sum = 0
  let codePointCount = 0

  for (const character of text) { // code points, not UTF-16 indexes
    codePointCount += 1
    sum += metrics.byRank[rank].advances[character]
      ?? fallbackBand(character) // latin / cjk / combining
  }

  const fontSize = style.fontSize ?? DEFAULT_TYPOGRAPHY.byRank[rank].fontSize
  const letterSpacing = style.letterSpacing ?? DEFAULT_TYPOGRAPHY.byRank[rank].letterSpacing
  const spacing = letterSpacing * Math.max(0, codePointCount - 1)
  return sum * fontSize * metrics.safetyFactor + spacing
}

// No getBBox(), getComputedTextLength(), getTotalLength(),
// getBoundingClientRect(), canvas, or browser globals.
→

Why ban DOM measurement? jsdom throws on the browser APIs and happy-dom returns zero. A test that measures zero says every label fits and hides the bug. The pure model produces the same answer on server, client, worker, and test runner.

Capabilities and boundaries

What fonts can do here.

The system can support more fonts, but each one needs a deliberate metrics contract. This is the capability map to use before asking for a new family.

Consumer contract

Changing the font means changing the policy input.

A consumer can theme the family, but a wider family should not be a silent CSS-only override. Typography lives in the planner’s policy because it affects layout decisions, including the rank style used by measureText().

const typography = {
  ...DEFAULT_TYPOGRAPHY,
  family: "Your measured family, system-ui, sans-serif",
  metrics: YOUR_GENERATED_METRICS,
}

planChart('line', size, shape, { typography })

The type contract is in packages/core/src/text-types.ts; the generator is scripts/generate-font-metrics.mjs; the research rationale is research/41-text-metrics.md.
