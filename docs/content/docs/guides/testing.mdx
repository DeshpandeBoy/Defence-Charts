title: Testing
description: Drive resize deterministically and assert chart meaning instead of brittle markup order.
---

`@shiftcharts/testing` provides deterministic observation and semantic markup helpers.

## ResizeObserver

```ts
import { FakeResizeObserver } from '@shiftcharts/testing'

const observer = new FakeResizeObserver(callback)
observer.observe(element)
observer.emit(320, 180, { target: element })
```

The fake is injected; tests do not patch a global observer and do not depend on browser timing.
The common one-target call can omit `target` and simply use `observer.emit(320, 180)`. Pass
`{ legacy: true }` when a test specifically needs to cover the `contentRect` fallback; the default
emits both `contentBoxSize` and `contentRect`, matching the path real browsers use.

## Markup helpers

The package exports `parseChart`, `expectLine`, `expectAxisTicks`, `expectPoints`, `expectScale`, and
`expectElementSet`. They parse a markup string with jsdom while each test remains in the Node
environment.

## What to assert

- The plan changes at the intended family boundary.
- A missing value breaks a line instead of falling to zero.
- `resolveFrame().plot` exactly matches `resolvePlotBox()`.
- Repeated rendering produces character-identical path data.
- Server rendering returns SVG without a DOM global.
- The element set contains no token-controlled SVG `<line>` geometry.
- A live resize wobble inside the 1% deadband keeps the previously accepted size family, then
  changes once the boundary is cleared.
- A `PlanPolicy` changes a decision before resolution, while a `PlanOverrides` patch changes only
  the already-resolved plan.

Avoid snapshots that only prove object key order or generated IDs. Prefer assertions that name the
meaning a user would lose if the behavior regressed.
