Responsive chart + dashboard grid library

We are building charts that change what information they show when their box changes size. A small chart becomes simpler and more honest, not merely smaller and harder to read.

In one sentence: the grid gives a chart a box, the core decides what fits, and a pure SVG layer draws that decision.

Grid gives a box12 columns, width, height, rows and columns
React measures itResizeObserver reports the current size
Core makes a planplanChart() returns plain, serialisable data
Primitives draw SVGHook-free, server-safe, styled by tokens

    03

    Core chooses one complete plan

    planChart() combines chart type, box, data shape and policy. It selects one rung, then applies any explicit consumer overrides after the decision.

    @gx/core
    Implemented for line + area
    The public call and its three internal movespackages/core/src/plan-chart.ts
    const plan = planChart('line', ctx, shape)

// Inside planChart():
const policy = resolvePolicy(inputPolicy)
const rung = LINE_RUNGS[ctx.sizeClass]
return applyOverrides(rung({ type, ctx, shape, policy }), overrides)

    Translation: “Use the Strip recipe, make a full decision, then honor any values the developer deliberately forced.”

    04

    The ChartPlan is a written instruction sheet

    The result contains no SVG and no browser objects. It is plain data that is easy to save or send, saying what exists, what is absent and how honest the chart can be at this size.

    06

    Tokens style the SVG without changing its meaning

    CSS variables choose color, type, stroke and spacing. Fit-sensitive typography is generated from the same typed source as core's font metrics, so browser text and planner math agree. Thresholds that change the plan stay in serialisable TypeScript policy instead of the CSS cascade, keeping server and client decisions identical.

    Choose how the chart will live in your application

    Route 1: fetch and draw on the server

    Use this when the chart's dimensions are known. Your mapping code translates the API names; planChart() sees only counts; Chart receives the real values and produces SVG before the browser loads the page. 

    // app/revenue/page.tsx — current source API
import '@gx/tokens/theme.css'
import {
  describeShape,
  planChart,
  sizeContextFromPixels,
  type Series,
} from '@gx/core'
import { Chart } from '@gx/primitives'

type RevenueRow = {
  period: string
  total_revenue: number
  predicted_revenue: number
}

export default async function RevenuePage() {
  const response = await fetch('https://api.example.com/revenue')
  if (!response.ok) throw new Error('Revenue data could not be loaded')

  const payload: { results: RevenueRow[] } = await response.json()
  const x = (row: RevenueRow) => new Date(`${row.period}-01T00:00:00Z`)
  const data: Series[] = [
    {
      id: 'actual',
      label: 'Actual',
      points: payload.results.map(row => ({ x: x(row), y: row.total_revenue })),
    },
    {
      id: 'forecast',
      label: 'Forecast',
      points: payload.results.map(row => ({ x: x(row), y: row.predicted_revenue })),
    },
  ]

  const dimensions = sizeContextFromPixels(600, 300)
  const plan = planChart('line', dimensions, describeShape(data))

  return <Chart plan={plan} data={data} ctx={dimensions}
    title="Monthly revenue" />
}

    Why the boundaries matter

    The rules protecting the idea

    These are not style preferences. Each rule prevents a known failure: hydration mismatch, unreadable charts, fake test results, broken themes or resize loops.

    Core has no DOM

    The same plan must be computable in Node, a worker or the browser. Text fitting uses metrics, not element measurement.

    The plan is plain data

    No functions, dates or hidden state. A ChartPlan can be serialized, snapshotted, cached and inspected.

    Small charts stay honest

    Below the readable-value threshold, the y-axis is removed. Concealed content leaves the DOM completely.

    CSS changes appearance only

    Colours and strokes can change per widget. Anything that changes what fits must enter the typed plan input.

    The box never follows content

    The grid decides outer size; the plan only changes descendants. This structurally prevents ResizeObserver loops.

    Gates fail on purpose

    The repo tests that invalid tokens and boundaries are rejected, not only that valid code passes.
