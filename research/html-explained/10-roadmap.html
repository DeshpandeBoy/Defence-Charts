Milestone map

What is done, what follows.

Use the status tags as a reading aid, not as a release promise. “Complete” means the repository has the relevant implementation and tests; publishing and broader consumer proof are separate gates.

A1 / foundation
complete

Package boundaries and trust rules

Dependency direction, DOM ban, token gate, client-directive survival, and deterministic test setup.

A2–A3 / planner
complete

Responsive ladder and ChartPlan

Six size families, complete line/area rung specs, policy inputs, overrides, plot layout, label degradation, and invariants.

A4 / renderer
complete

Server-safe SVG and data frame

Canonical data, scales, ticks, paths, points, axes, labels, values, tables, and RSC fixture proof.

A5–A6 / client + motion
implemented / verify continuously

AutoChart, resize, motion

ResizeObserver seam, containment checks, transition contract, reduced-motion behavior, and real-browser gates.

complete for current surface

Generated CSS, font metrics, token membership/naming, research-to-token dispositions, and typed thresholds.

Two agent lanes, one truth

Parallel work without losing the handoff.

Codex owns implementation and reproducible verification. Claude owns bounded research and independent review. The coordinator owns shared integration files and final task status.

Codex / build

One task, one write set

Grid, interaction, chart-family, packaging, and release agents work in separate modules and worktrees. Central exports and unions are integrated once.

Claude / research

One question, one proposal

Research lands in unique evidence files. It labels primary facts, official implementation, artifact observations, inference, and product proposals.

Handoff / resume

Git and files carry context

Every task records its commit, changed paths, exact test results, blockers, remaining work, and resume command. Chat history is optional.

Immediate execution waves

What happens next.

The work is split only after shared contracts are frozen. That keeps parallel agents fast without making their changes incompatible.

1 / reconcile

Close stale decisions

Classify every open item from research 80–83 against locked decisions and the verified A/B baseline.

2 / freeze

Define C0 contracts

Lock stable widget identity, layout serialization, the RGL adapter, and the grid-to-chart measurement seam.

3 / build

Finish the real grid

Implement controlled drag/resize, compaction, widget chrome, keyboard access, persistence callbacks, and browser stress proof.

4 / preview

Prove packed consumers

Ship line/area plus grid from real tarballs after CSS, exports, RSC, Vite, metadata, and release automation pass.

5 / expand

Add complete families

Bar/timebar, donut, KPI/progress, scatter, heatmap, and funnel each repeat the planner, renderer, access, and browser proof.

6 / launch

Audit every public claim

Install the release candidate from packed artifacts, run the full matrix, update all derived docs once, then publish Free v1.

The finish line

Understandable, extendable, honest.

The project is successful when a new contributor can answer: where does this decision live, what data does it consume, what does the consumer control, and what proof says it works?

Where?

One package and one source file owns the decision.

What?

Plain data enters; a complete plan and accessible SVG leave.

Proof?

Tests, generated-output checks, and browser evidence distinguish implemented, planned, and unresolved.
