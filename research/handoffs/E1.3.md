# E1.3 — Packed tarball consumer fixtures

## Objective

Prove that clean React, Next App Router/RSC, and Vite consumers can resolve the six published
package roots, six published CSS subpaths, declarations, and package metadata from local packed
artifacts without workspace links, source imports, or network access.

## Implementation

- Added three committed fixture templates under scripts/consumer-fixtures/e1.3:
  - react-consumer: React 19 plus the Vite React build, direct Chart and AutoChart usage.
  - next-rsc-consumer: server Chart route plus an explicit use-client AutoChart boundary route.
  - vite-consumer: plain Vite TypeScript entry importing all six package roots and CSS subpaths.
- Added scripts/check-consumers.mjs:
  - checks fixture source coverage and rejects workspace protocols, repository package paths, source
    entry imports, and node_modules reach-through;
  - checks built JS/CSS inputs, packs all six packages with local pnpm pack, and extracts those
    tarballs into each temporary consumer;
  - links only non-library peer/tool packages from the existing local pnpm store, never from a
    workspace package;
  - verifies every package root resolves from the temporary extracted package and has a matching
    declaration, MIT metadata, ESM metadata, and dist target;
  - verifies all six CSS subpaths resolve to dist;
  - typechecks and builds each consumer with local TypeScript/Vite/Next binaries;
  - verifies Next server HTML contains the SVG graphics role and the client bundle contains the
    explicit AutoChart boundary without source package paths.
- Added scripts/check-consumers.test.mjs for the committed fixture source contract.

## Deliberate offline harness decisions and attempted failures

- A temporary pnpm install with exact dependencies was attempted and failed before any build with
  ERR_PNPM_NO_OFFLINE_META because the local pnpm metadata mirror did not contain TypeScript
  metadata. The committed proof therefore avoids that registry-resolution path: it uses pnpm pack
  for the six library packages, tar-extracts them into a clean temporary node_modules tree, and
  links only already-installed non-library tools and peers from the local pnpm store.
- Next Turbopack rejected a symlinked Next package whose real path was outside the temporary
  consumer. The harness copies only the local Next tool package into the temporary root, links
  its local store dependencies, and runs next build --webpack. The RSC/App Router contract is
  unchanged and the server route is asserted from generated HTML.
- A standalone Next output trace attempted to create a path outside the temporary root through
  local store links. The fixture does not request standalone output because deployment tracing is
  outside E1.3; the ordinary App Router production build passes.
- Node 22.12.0 emitted the repository's existing engines warning requiring >=22.18. The focused
  checks themselves passed; release verification should rerun on the supported Node 24 runtime.
