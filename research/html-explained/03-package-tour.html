03 / Package tour

Six packages. Six jobs.

The workspace is a monorepo because the seams matter. A consumer can take the core planner without React, the SVG primitives without the grid, or the full adaptive stack when the product needs it.

Packaging principle. Importing one layer should not silently pull in every chart, every browser behavior, or every framework boundary.

Package responsibilities

Start with the job, then the code.

Read each package as a promise. The source files named here are the best place to continue once the concept is clear.

foundation

@gx/tokens

Role: the visual vocabulary. It owns typed token data, generated CSS, Rail and Neutral themes, typography CSS, and theme names.

Exports: token names and the theme.css CSS subpath.

Depends on: nothing. That makes it safe to consume from any styling setup.

packages/tokens/src/tokens.ts · packages/tokens/src/themes/theme.css

implemented

@gx/core

Role: the brain. It classifies size, resolves a complete plan, computes layout, ticks, text fit, and coordinates.

Exports: planChart, ChartPlan, SizeContext, DataShape, resolveFrame, measureText, and policy types.

Depends on: d3-array, d3-format, d3-scale, d3-shape, d3-time-format.

packages/core/src/index.ts · packages/core/src/plan-chart.ts

implemented

@gx/primitives

Role: the hook-free SVG renderer. It turns a plan and data into chart markup: axes, grid, paths, points, labels, values, horizon bands, and a data table.

Constraint: no state, effects, refs, or react-dom. It can render in a server component.

Depends on: @gx/core and React as a peer.

packages/primitives/src/index.ts · packages/primitives/src/Chart.tsx

implemented seam

@gx/react

Role: the optional client boundary. AutoChart observes the actual element, creates a size context, and reuses the core + primitives path.

Constraint: interaction belongs here, not in the resolver. Tooltips, crosshair, brush, and legend interaction are reserved work.

Depends on: @gx/core, @gx/primitives, React.

packages/react/src/AutoChart.tsx · packages/react/src/useElementSize.ts

boundary shell

@gx/grid

Role: dashboard placement. It supplies a 12-column grid and reports the widget box to the chart.

Constraint: it never chooses what the chart shows. This package is the “where” layer, not the “what” layer.

Depends on: @gx/react, react-grid-layout, React.

packages/grid/src/index.ts · packages/grid/package.json

dev-facing

@gx/testing

Role: deterministic proof. It provides a controllable fake ResizeObserver, semantic chart assertions, and helpers for lines, axes, points, scales, and element sets.

Constraint: test doubles are injected and driven explicitly; they do not become production globals.

Depends on: @gx/core at runtime and Vitest/jsdom in development.

packages/testing/src/index.ts · packages/testing/src/expect.ts

How a consumer composes them

The package stack is optional.

There is no requirement to install the whole workspace. The smallest useful path depends on whether the consumer already owns the box and whether the chart needs to react to resize.

Consumer needUseWhy
Plan a chart in a server or worker@gx/corePure plan data; no React and no DOM.
Render a server-safe SVG@gx/core + @gx/primitives + tokens CSSOne explicit plan, one renderer, no resize loop.
React chart in a known-size layoutCore + primitives in your componentStatic chart; no client boundary required.
Chart adapts to its own box@gx/react AutoChartResizeObserver is isolated to the client layer.
Dashboard drag and resize@gx/grid + @gx/reactGrid owns layout; AutoChart reads the resulting box.

High-level code

One public path to remember.

The actual source has more types and guardrails, but this is the mental model to keep in your head while reading it.

// 1. Your app owns data and describes its shape.
const shape = { seriesCount: 2, pointCount: 12, hasNegative: false }

// 2. Core turns the box into a semantic plan.
const plan = planChart('line', sizeContextFromPixels(320, 180), shape)

// 3. Primitives draw the plan; tokens style the output.
<Chart plan={plan} data={series} />

// 4. If the box is not known, AutoChart owns only the measurement loop.
<AutoChart type="line" data={series} initialSize={initialSize} />
→

The key handoff is plain data. A plan can be snapshot-tested, JSON round-tripped, rendered on the server, and inspected without running a browser.
