# VT-001-donut-micro-total — Fix VT-001 — donut Micro shows the wrong compact total

## Objective

Fix only VT-001 from `research/agent-work/claude/CR-VT01-visual-family-audit.md`: donut Micro's
compact value read "0 total" instead of the fixture's true sum, 107. VT-002 through VT-011 are out
of scope for this task.

## Root cause and fix

`fitValueDisplay()`'s `'donut-total'` mode (`packages/core/src/frame.ts`) summed
`s.arcs.reduce((sum, arc) => sum + arc.value, 0)`. `SeriesFrame.arcs` is built only when
`mark.kind === 'arc'` — donut's mark is `'none'` at Micro, so `arcs` was always empty there and the
total silently summed to 0.

Fix: sum `s.points` instead — `SeriesFrame.points` holds every defined point regardless of mark
kind ("**Every** defined point, always", per its own doc comment), so it is available at Micro. The
sum is unchanged at rungs where arcs already exist: `donutArcs()` partitions the same raw values
into visible/`Other` slices without loss, so raw-point sum and arc-built sum are always numerically
equal for valid (non-negative, finite) data. Larger-rung behavior is therefore unaffected.

Also widened `scripts/check-family-matrix.mjs`'s donut assertion block, which previously only ran
under `card.rung !== 'micro'` — structurally unable to catch this defect at Micro regardless of the
renderer fix. The "107 total" value-text check now runs unconditionally for Micro/Tile; the
arc-geometry/Other-bucket/panel-key/legend checks stay gated to non-Micro rungs, where they still
correctly apply.
