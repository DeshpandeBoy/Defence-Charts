## Method

- Counts run in ascending order: `1`, `10`, `50`, `100`, `200`.
- Every count starts from a controlled empty layout, then performs 2 warm-up transitions and 5
  measured transitions to the requested count.
- Each transition uses the same deterministic 3×2-cell layout in four columns. IDs are
  `stress-0000` through `stress-N`; the layout fingerprint is compared across all measured samples.
- Layout latency is recorded with page-side `performance.now()` at controlled request, React commit,
  and after three animation frames with all grid item rectangles read. Timings include React mount,
  RGL layout, shell chrome, AutoChart measurement/planning, and SVG rendering.
- The fixture records `onLayoutChange` and `onLayoutCommit` counts, callback item counts, identity
  failures, and a quiet-frame check. Browser console/page errors are checked for ResizeObserver loop
  errors.
- Memory uses Chromium DevTools `Performance.getMetrics` JavaScript heap values when available. The
  runner records `available: false` if the browser cannot expose that metric; it does not fabricate OS
  available memory.
- `performanceBudget` remains `null`.

## Limitations and corrected implementation issues

- The memory trend is Chromium JavaScript heap usage/capacity from the DevTools Performance domain,
  not operating-system available RAM. If that domain and `window.performance.memory` are absent, the
  result records `available: false` instead of inventing a value.
- C4.2 measures controlled layout population, not pointer drag, resize, keyboard, RTL, hidden-tab, or
  forced-colors behavior; those remain C4.1 coverage. The stress fixture uses read-only mode to
  isolate layout population and includes the real shell/chart composition.
- The first runner attempt exposed a same-count `0 → 0` promise path, and the first syntax check
  exposed an incorrect `dirname` import. Both were corrected before the passing run; no failed
  measurement was recorded as evidence.
- Results are evidence for this headless Chromium/Node/macOS context, not a universal performance
  benchmark. No threshold or CI gate was added.
