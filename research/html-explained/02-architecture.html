02 / Architecture

One direction. Narrow jobs.

The dependency graph moves from data and visual vocabulary toward rendering and interaction. Each boundary exists because a tempting shortcut would make the system harder to test or harder to use from a server.

Read the arrows as ownership. The grid gives a size. React reports it. Core makes the plan. Primitives draw it. Tokens style it. Testing proves the boundaries.

Two rendering paths

Static when you can. Reactive when you need to.

The same primitives can be used in a server component or behind an optional client layer. This keeps the default path small and gives the consumer an explicit choice.

server-safe path

Chart + plan

Your app calls planChart() or supplies a plan. @gx/primitives renders SVG. No ResizeObserver, no hydration requirement, and the RSC fixture verifies that the chart is in the HTML.

const plan = planChart('line', size, shape)
return <Chart plan={plan} data={series} />
client path

AutoChart

@gx/react observes the element, converts pixels to a SizeContext, calls the same resolver, and passes the new plan to the same renderer. The client owns time; core still owns meaning.

<AutoChart
  type="line"
  data={series}
  initialSize={{ width: 320, height: 180 }}
/>

Guardrails

Architecture is also what we forbid.

The rules below are enforced by lint, dependency checks, generated-output checks, tests, and browser fixtures. They are not just documentation preferences.

No React in core

The planner stays usable from Node, a worker, another framework, or a server component.

No DOM measurement in core

Browser APIs such as getBBox() are banned. The text model is deterministic and testable.

No raw styling literals in components

CSS values travel through tokenized custom properties; the token gate tests both rejection and allow cases.

No client directive in primitives

Only the interaction layers carry the client boundary, preserving server rendering.

No content-determined box

Plans subdivide the measured box; they do not name an outer width or height.

No silent unsupported chart fallback

Today, planChart() intentionally throws for types whose milestones have not landed.
