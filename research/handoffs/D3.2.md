# D3.2 — Progress family

## Objective

Ship an explicit, pure progress planner and RSC-safe renderer that changes encoding across the
responsive ladder: radial completion at Micro/Tile, a horizontal completion bar at Strip and
larger rungs, and visible current/target/remaining/over-target/indeterminate semantics that do not
depend on colour. Progress must be a registered family and must never fall back to KPI, donut, or
line when its target or current value is missing.

## Decisions and assumptions

| Item | Class | Evidence | Effect |
|---|---|---|---|
| Radial at Micro/Tile, horizontal bar at Strip+ | Locked responsive source | `research/10-responsive-ladder.md` §4 Progress | Planner must encode a real mark substitution, not only resize a ring |
| Current is the latest finite point | Existing canonical data contract | `packages/core/src/frame.ts` and D3.1 value semantics | No new fetching or persistence; null remains missing |
| Target comes from optional series metadata | Shipped D3.1 contract | `packages/core/src/data.ts` | Missing/non-finite targets remain explicit and are never inferred |
| Completion ratio is clamped to [0,1] for geometry | Implementation contract | Progress geometry requires finite bounded fill | Over-target is separately exposed as text/data |
| Progress gets an explicit mark/geometry seam if existing arc/bar frames cannot represent target-aware completion | Architecture guard | `CR-D00` identifies the open KPI/progress mark question | Do not encode progress as misleading donut slices or a line fallback |
| Horizontal track thickness is derived from the project-owned plot height | Implementation assumption | Existing core plot geometry; covered by frame tests and browser matrix | Keeps the progress mark serialisable and token-independent while preserving responsive substitution |
