## Objective

Move the Micro, Tile, and Strip representation fixes into the serialisable chart contract and
static primitive renderer. The fixture shell and CSS may support the result, but must not be the
primary solution. The rendered chart must explain its information hierarchy at a glance:

- Micro: a readable, labelled latest value with useful context and no misleading empty plot.
- Tile: a primary metric with context/delta and a deliberate sparkline/shape treatment.
- Strip: a compact trend shape whose axis/summary treatment communicates what is and is not shown.

## Acceptance criteria

1. Core plans and frame data remain pure, serialisable, stable-identity, and compatible with the
   existing family consumers unless a tested contract extension is required.
2. Micro, Tile, and Strip render semantically distinct information, not just different CSS sizes.
3. Value entries expose their series/context meaning in the visual and accessible static output.
4. Existing negative, boundary, accessibility, RSC/static, family, and package tests remain green.
5. `git diff --check` passes; browser proof covers the fresh family matrix at the demo URL.

## Implemented

- Core `ChartFrame.value` now carries explicit `presentation` semantics: series labels are part of
  the fitted value composition and Tile context is explicitly delta context.
- Micro and Tile fit labels together with their value/delta, keep the first readable entry, and
  expose the omitted-series count instead of presenting unlabeled numbers.
- Primitives render the label/value pairing, accessible compact summaries, and overflow meaning;
  every series also has a stable SVG title for the static/RSC path.
- Line/area Strip keeps `shape-only` value honesty but uses a compact internal legend so several
  colored shapes are visually interpretable. The shared Strip seed used by other families remains
  unchanged.
- Updated the shared family acceptance expectation and static element snapshots for the shipped
  representation.
