---
title: AutoChart
description: The client boundary that measures a box, resolves a plan, and renders Chart.
---

```tsx
import { AutoChart } from '@shiftcharts/react'
```

`AutoChart` carries the package's `"use client"` boundary. It observes one wrapper, derives
`SizeContext` and `DataShape`, applies the pure size classifier's fractional deadband, calls
`planChart`, and passes the result to `Chart`.

## Props

| Prop | Type | Required | Meaning |
| --- | --- | --- | --- |
| `type` | `ChartType` | Yes | One of the ten registered chart types: `line`, `area`, `bar`, `timebar`, `donut`, `scatter`, `funnel`, `kpi`, `heatmap`, or `progress` |
| `data` | `readonly Series[]` | Yes | Canonical values |
| `title` | `string` | Yes | Accessible chart name |
| `description` | `string` | No | Longer accessible description |
| `policy` | `Partial<PlanPolicy>` | No | Typed thresholds and fitting inputs applied before resolution |
| `overrides` | `PlanOverrides` | No | Forced `ChartPlan` values applied after resolution |
| `nominalCellSize` | `number` | No | Tier-C standalone pixel-to-cell conversion; default is 100 |
| `initialSize` | `{ width; height }` | No | Declared server-rendered first size |
| `className` | `string` | No | Wrapper class |
| `id` | `string` | No | Stable generated SVG IDs, useful in snapshots |

## First render

Without `initialSize`, server output contains the wrapper and no guessed chart. With `initialSize`,
the server emits a real first chart. After hydration, the observer supplies the real dimensions.

## Rung stability

The pure `planChart()` contract has no direction memory. A live `AutoChart` keeps the last accepted
size class at the client boundary and uses a 1% fractional deadband around rung minimums, so a
slow resize wobble does not repeatedly mount and unmount a rung's marks. The first real measurement
is accepted immediately; a server-declared `initialSize` remains deterministic.

## Threshold policy and overrides

B3 keeps plan inputs separate from presentation. `policy` carries serialisable TypeScript values
such as `tickTargetSpacingX`, `plotHeightOptimal`, `substitute`, `pointBudget`, and
`valueRegionMaxShare`. They are applied before `planChart()` resolves a rung, so the same inputs
produce the same plan on the server and client.

```tsx
<AutoChart
  type="line"
  data={series}
  title="Revenue"
  policy={{ tickTargetSpacingX: 80, pointBudget: 1000, substitute: true }}
/>
```

`overrides` is intentionally different: it is a `PlanOverrides` deep partial applied after the
resolver and can force a decided plan field. It is not a second spelling of a threshold. For
example, changing `marks.pointBudget` after resolution does not re-run the renderer decision.

Threshold defaults carry provenance in the core policy source: A-lit is published perception or
platform research, A-impl is a verified library convention, B is an evidence-consistent ShiftCharts choice,
and C is an explicit unsourced design choice. Presentation values such as color, stroke, radius,
and opacity remain CSS custom properties; they never feed `planChart()`.

| Typed input | Default | Provenance |
| --- | ---: | --- |
| `tickTargetSpacingX` | `100px` | A-lit — Talbot 2010 |
| `plotHeightOptimal` | `24px` | A-lit — Heer 2009 |
| `aggregateAfter` | `8` | B — ShiftCharts choice consistent with legend scannability research |
| `pointBudget` | `2000` | C — rendering budget, not a perception claim |
| `minCellSize` | `8px` | C — explicit future heatmap cell-floor choice (`@future`) |
| `valueRegionMaxShare` | `0.5` | C — explicit unsourced layout budget |
| `nominalCellSize` | `100px` | C — standalone conversion default |
