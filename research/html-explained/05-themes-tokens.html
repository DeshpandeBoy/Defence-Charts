05 / Themes + tokens

Many tokens. One vocabulary.

The theme system looks large because it separates meaning, presentation, and evidence. A chart can change ground, ink, series, spacing, strokes, typography, interaction, and motion without the component inventing values locally.

Token rule: if a value is part of the visual system, name it once, generate its CSS, and let a theme rebind it. If changing it changes what information the chart claims, it belongs in PlanPolicy instead.

Why so many tokens?

Because a chart has more visual channels than color.

A series can be distinguished by hue, but a theme also needs to preserve reading order, contrast, density, state, and motion. The token tree makes those decisions inspectable.

Surface + neutral ramp

Ground, plot, borders, widget padding, gap, radius, shadow, and a numbered neutral ramp.

Series + marks

Six series colors plus line stroke, point radius, area opacity, bar geometry, arc geometry, and horizon-band opacity.

Axes + grid

Visibility, tick spacing, tick length, domain lines, grid opacity, minor ticks, dash, cap, and axis translation.

Labels + typography

Font family, size ranks, label limit, overlap mode, separation, rotation, stagger, value-label halo, and landmark grade.

Legend + interaction

Legend gaps, symbol shape, entry limits, tooltip, crosshair, hover neutral, and interaction label geometry.

Motion + size

Rescale/recompose duration, easing, stage delay, reduced-motion-compatible transitions, gap, scale ratios, and breakpoints.

The two theme families

Rail is the instrument. Neutral is the escape hatch.

There are four shipped theme scopes: Rail dark, Rail light, Neutral dark, and Neutral light. They are not four unrelated palettes.

Rail / default world

Emission + absorption

The Rail palette uses named emission wavelengths for the series ramp and a charcoal continuum. Rail dark is the reference; Rail light re-solves the same six series against a bright ground.

1H-beta
2Na I D₂
3Mg b₂
4H-delta
5He I
6Fe I

Rail series are defined in DESIGN.md and generated into theme.css.

Neutral / explicit alternative

Conventional neutral palette

Neutral keeps the same token contract but swaps in a conventional grey surface, a different series set, non-zero radius, and shadows. It exists so a consumer can preserve the API while adopting a more familiar visual language.

How the token path works

From source to screen.

CSS is the output, not the provenance source. The typed tree is where tiers and sources stay attached to each value.

.defence-theme {
  --gx-surface-color: #10181b;

  --gx-series-2: #ffc48f;
  --gx-line-stroke-width: 2px;
}

Token vs policy

Do not theme semantics by accident.

This is the split that keeps the library understandable. A theme can change how an axis looks. It should not secretly change whether the chart claims value legibility.

QuestionPresentation tokenPlan policy
How dark is the gridline?--gx-grid-opacityNot policy.
How many x ticks are allowed?Not a CSS token.axes.x.ticks.count and policy thresholds.
How thick is a line?--gx-line-stroke-widthNot policy.
Should the y-axis be visible?Theme may style it, not decide it.Rung + valueLegibility.
Which typeface is used?--gx-font-family plus typography tokens.Metrics must travel with the typography input if widths change.
When should a mark become a horizon?Not CSS.Plan policy / rung threshold.

Known limitation

Light theme separation is harder.

On a bright ground, colors must be darker to keep contrast. That compresses the usable lightness range and lowers pairwise separation. The guide keeps this visible instead of calling light a simple inversion.

⚠

Do not add a new series color by eye. Name its source line or define the derivation, test contrast, run color-vision and greyscale checks, and add it to the typed token tree so the generated output and evidence stay together.
