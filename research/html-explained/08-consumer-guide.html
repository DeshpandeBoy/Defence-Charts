08 / Consumer guide

Make it yours without breaking the contract.

A consumer can use only the layers they need, apply a theme scope, supply a measured font contract, and still get the same responsive planning model.

Practical path: install the package set → import the token CSS → choose static or AutoChart → feed serialisable data → override scoped tokens → verify your own fonts and data shape.

Install shape

Choose the smallest package path.

The workspace manifests are private and still 0.0.0-versioned, so treat this as the intended consumer contract for the project rather than a published registry command today.

# static / server-safe chart
pnpm add @gx/core @gx/primitives @gx/tokens

# responsive React chart
pnpm add @gx/core @gx/primitives @gx/react @gx/tokens

# dashboard shell as well
pnpm add @gx/grid
!

Before publishing externally: package exports, generated CSS subpaths, tree-shaking, peer dependencies, and provenance still need the release gates described in the implementation plan.

Static rendering

When the box is already known.

Static rendering is the simplest mental model: your application owns the size, core makes the plan, and primitives render it.

React component

import '@gx/tokens/theme.css'
import { Chart } from '@gx/primitives'
import { planChart, sizeContextFromPixels } from '@gx/core'

const size = sizeContextFromPixels(480, 280)
const plan = planChart('line', size, shape)

export function RevenueChart() {
  return <Chart plan={plan} data={series} />
}

What you control

  • Data fetching and data shape.
  • Known width and height.
  • Theme scope and token overrides.
  • Policy values, when you have evidence for a different default.

You do not need to reimplement the rung logic or manually hide SVG elements.

AutoChart rendering

When the box changes.

Use AutoChart when the chart should respond to the actual element rather than a size known by the parent.

Client-aware component

import { AutoChart } from '@gx/react'
import '@gx/react/auto-chart.css'

<AutoChart
  type="line"
  data={series}
  initialSize={{ width: 320, height: 180 }}
  dataShape={shape}
/>

What happens on resize

  1. ResizeObserver reports the element.
  2. Pixels become SizeContext.
  3. Core resolves a new complete plan.
  4. The same primitives rerender.
  5. CSS transition handles allowed motion; reduced motion removes the enhancement.

Theme your consumer

Scope overrides around your application.

Use a class or data attribute so the override is local. Keep the component’s CSS tokenized and keep plan-affecting changes in TypeScript policy.

<div class="defence-theme">
  <AutoChart type="line" data={series} />
</div>

.defence-theme {
  --gx-surface-color: #10181b;
  --gx-surface-text-color: #e7f5f8;
  --gx-series-1: #9ce7ff;
  --gx-series-2: #ffc48f;
  --gx-widget-radius: 4px;
}

/* For a built-in family: */
<div data-gx-theme="neutral-light">…</div>

Data contract

Bring data in a plain shape.

The library does not fetch, own, or mutate your dataset. It receives canonical serialisable series and a small shape description so planning can stay independent of application code.

Series

Each series has an id/name and ordered data points. Values remain the source of truth; the frame computes coordinates.

Shape

Count series and points, note negative values, category density, and other facts the planner needs before it sees coordinates.

Overrides

Use deep partial plan overrides for an explicit consumer decision, but treat them as an escape hatch and test the resulting plan.

Source: packages/core/src/data.ts · packages/core/src/policy.ts.

Consumer checklist

Before you call it integrated.

A consumer integration is not complete when the import compiles. It is complete when its visual and data assumptions match the planner.

1Load the token CSS. Confirm the chart has a theme scope and no unresolved var(--gx-…).
2Choose server or client intentionally. Static charts should not inherit a resize loop accidentally.
3Verify real data. Empty arrays, negative values, long labels, many series, and missing periods must be part of your fixtures.
4Verify the actual font. If it differs from Roboto Flex, provide matching metrics instead of only overriding CSS.

Do not silently fork the resolver

If the product needs a different threshold or a different rung, prefer a typed policy or a new chart-family decision record. A local CSS hack can change appearance, but it cannot change whether an axis is semantically justified.
