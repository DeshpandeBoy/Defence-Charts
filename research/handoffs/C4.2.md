## Known limitations and corrected implementation issues

- The memory trend is Chromium JavaScript heap usage/capacity from the DevTools Performance domain,
  not operating-system available RAM. If that domain and `window.performance.memory` are absent,
  the result records `available: false` instead of inventing a value.
- C4.2 measures controlled layout population, not pointer drag, resize, keyboard, RTL, hidden-tab,
  or forced-colors behavior; those remain C4.1 coverage. The stress fixture uses `read-only` mode
  to isolate layout population and includes the real shell/chart composition.
- Timings include React mounting, RGL layout, WidgetShell chrome, AutoChart measurement/planning, and
  SVG rendering. They are not an isolated react-grid-layout algorithm benchmark.
- The first runner attempt exposed a same-count `0 → 0` promise path in the fixture, and the first
  syntax check exposed an incorrect `dirname` import. Both were corrected before the passing run;
  no failed measurement was recorded as evidence.
