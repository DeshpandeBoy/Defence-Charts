## Acceptance criteria after gate clears

- Versioned serialization and migration are deterministic and immutable.
- Duplicate and missing widget IDs, invalid layouts, constraint changes, and migration failures have explicit behavior.

## Accepted policy choices

- Migrations are sequential and keyed by source version.
- Missing/unset versions are rejected because no pre-versioned public release exists.
- Future versions fail with a distinct `future-version` code.
- The current widget set is authoritative: removed IDs are dropped; added IDs use an explicit
  default placement or append below as a deterministic fallback.
- Changed constraints clamp saved sizes/positions, then the grid adapter uses the pinned RGL core
  compactor to settle collisions.
- Rename detection, storage, save failures, and multi-writer conflict policy remain host-owned.

## Completion checkpoint

- Implemented a pure, sequential migration runner keyed by source version. Missing migration steps,
  skipped versions, thrown migrations, future versions, and invalid version values fail with typed
  `LayoutValidationError` codes.
- Added current-widget reconciliation: removed IDs are dropped, new widgets use explicit placement or
  append below, current constraints replace stale constraints, and geometry is clamped without
  mutating host values.
- Added the grid-level adapter that sends the reconciled snapshot through pinned RGL 2.2.4 bounds and
  vertical-compaction logic to settle collisions deterministically.
- Documented the host-owned storage boundary and updated the public roadmap to distinguish the
  implemented release candidate from account-level npm publishing prerequisites.
