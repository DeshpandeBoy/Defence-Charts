## Objective

Deepen the compact line/area SVG representation so resizing preserves useful meaning, not only
geometry. The current audit found four concrete failures in the rendered matrix:

1. The demo renders nominal square viewBoxes into short card frames, reducing planned value text
   to roughly 4–6 CSS px.
2. Micro reserves a blank plot region even though its plan intentionally draws no mark.
3. Tile displays one latest value for a six-series plot without enough visible identity context.
4. Strip's internal legend is not charged by core layout and overlaps its marks.

The result must remain pure/serialisable in `@gx/core`, hook-free/RSC-safe in `@gx/primitives`,
and must make the information contract explicit at each compact rung.

## Acceptance criteria

1. Micro uses its available value surface for a readable primary metric and context; no empty
   plot claims space when the plan draws no mark.
2. Tile makes the relationship between the visible metric and the visible series explicit, with
   useful context at normal and narrow card widths; no misleading unlabeled lines.
3. Strip reserves or otherwise safely places series identity so the legend/labels do not overlap
   the shape; its shape-only honesty contract remains intact.
4. The generated SVG stays deterministic, serialisable, static/RSC-safe, and accessible.
5. Browser evidence proves desktop and narrow widths; full tests, build, matrix gate, and
   `git diff --check` pass.

## Delivered implementation

The compact representation now preserves information through both the core frame and the SVG
consumer:

- `@gx/core` gives a no-mark Micro frame the available value surface instead of reserving an
  empty plot, exposes Tile value coverage, and makes the line/area Strip identity rail a
  single reserved row.
- `@gx/primitives` paints label context and the dominant metric as explicit SVG tspans, adds a
  deterministic static identity rail for Tile and Strip, and only applies a plot transform to
  fallback rails that core has not already reserved.
- The family matrix measures each card's actual chart box while preserving the row's semantic
  grid footprint, so its SVG `viewBox` follows the real responsive surface.
- `PlanPanel.tsx` reconstructs the new `ChromeSpec.plotPresence` field so the full playground
  typecheck remains green.

## Playground consumer checkpoint (2026-08-25)

The consumer-side fix is complete in the playground write set. The ladder cards now reuse
`@gx/react`'s `useElementSize` hook with the direct RSC-safe `Chart` renderer. Measured card pixels
drive `ctx.width`/`ctx.height` and the SVG `viewBox`; the row's `ctx.cols`/`ctx.rows` remain
authoritative for the semantic information budget and `data-plan-*` metadata. The normal and empty
state fixtures remain direct `Chart` consumers.

`AutoChart` was tested as the preferred composition but rejected for this fixture: its client
interaction overlay is mounted for interactive rungs, which violates the matrix's existing static
markup contract (`.gx-interaction` must be absent) and would make the static/RSC-safe acceptance
surface misleading. The final composition therefore reuses the canonical measurement hook without
adding the runtime interaction layer.
