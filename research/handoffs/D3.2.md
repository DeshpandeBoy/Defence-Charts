# D3.2 — Progress family

## Objective

Ship an explicit, pure progress planner and RSC-safe renderer that changes encoding across the
responsive ladder: radial completion at Micro/Tile, a horizontal completion bar at Strip and
larger rungs, and visible current/target/remaining/over-target/indeterminate semantics that do not
depend on colour. Progress must be a registered family and must never fall back to KPI, donut, or
line when its target or current value is missing.

- [ ] Pure progress planner covers Micro → Stage with an explicit radial-to-horizontal encoding
      substitution, orientation, value legibility, table presence, and interaction semantics.
- [ ] Progress geometry is serialisable, finite, stable by series identity, target-aware, and
      handles missing/null/non-finite/zero or negative targets as an explicit indeterminate state.
- [ ] Visible text/table semantics expose current, target, remaining, over-target, and the
      indeterminate/missing state; status is redundant text/data, not colour-only.
- [ ] Tests cover complete, partial, exact-target, over-target, missing target, missing current,
      one-point data, negative values, JSON round-trip, stable identity, and unsupported-family
      failure boundaries.
- [ ] Shared family matrix covers all six rungs, normal/empty/indeterminate states, accessible
      text, resize identity, themes, reduced motion, and no runtime/ResizeObserver errors.
- [ ] Run narrow family tests, package typechecks/lint/build, full verification, browser matrix,
