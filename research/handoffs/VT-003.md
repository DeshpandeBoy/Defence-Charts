# VT-003 — Donut/funnel category labels

## Objective

Fix the one confirmed CR-VT01 defect explicitly deferred out of `D0.2-visual-defects`: every donut
slice and funnel stage was labelled by its raw point index (`"0"`, `"1"`, …) because `DataPoint` had
no field to carry a real category/stage name. CR-VT01 diagnosed this as a data-model gap needing a
`packages/core` type decision before any fix — this task makes that decision (additive optional
field, option (a) from the CR-VT01 report) and implements it.

## Current checkpoint

### Completed

- `DataPoint.category?: string` added, with a doc comment explaining the `Series.label` parallel.
- `donutArcs()`/`funnelFrame()` wired to prefer `category`.
- `describeShape()`'s `labelMaxChars` now measures `max(formatXLabel(x).length, category?.length ?? 0)`
  — closes a real, verified gap: without this, a long category name would have been legible in the
  data but silently under-budgeted in layout (`packages/core/src/data.ts`'s own doc comment already
  asserted the invariant this restores).
- Family-matrix fixture: donut's 10 categories and funnel's 5 stages now carry real names
  (`Personnel`, `Training`, … / `Assigned`, `Screened`, …) instead of bare `x` indices.
- **Unplanned fallout found and fixed during verification, not part of the original VT-003 scope**:
  the browser gate failed on first run — `funnel-stage` at narrow (390px) overflowed its card. Root
  cause: the funnel Stage/`breakdown`-detail composed text
  (`"{label}: value V; share S%; conversion C%; drop-off D%"`, built in
  `packages/primitives/src/families/funnel/renderer.tsx`'s `stageText()`) has never had any
  width-awareness — it was only ever exercised with a 1-character digit label, so the defect was
  latent, not introduced by this task. Fixed by:
  - Adding `FunnelStageFrame.labelWidth` (`packages/core/src/frame.ts`) — the *true* available room
    for a stage's label (`plot.width`, in both orientations — verified by derivation, not guessed:
    every stage's label sits at the same horizontal position regardless of its own bar's share-scaled
    `width`, so budgeting against `width` would have wrongly over-degraded low-share stages).
  - `renderer.tsx`'s `stageText()` replaced by `stageTextTiers()` (same three wordings, kept as an
    ordered list) + `fitStageText()`, which picks the widest tier that fits `labelWidth` via
    `measureText()` (pure, DOM-free, already used the same way in `Labels.tsx`/`CompactSeriesKey.tsx`
    — not a new architectural pattern). Floor is always `"label: value"`; never fully hidden.
  - `policy` threaded into the funnel renderer (was already on `MarkRendererInput`, just unused
    before); `renderer.test.tsx`'s mocked `policy: {}` replaced with a real `DEFAULT_POLICY`, since
    `{}` would have thrown once `policy.typography.metrics` was actually read.
  - `renderer.test.tsx`'s and `fixture.ts`'s hand-authored frames given a realistic `labelWidth: 600`
    (calibrated against measured pixel widths, not guessed — see Verification evidence) so
    pre-existing composition-wording tests stay decoupled from the new degrade behavior; one new
    test (`'degrades stage text to a shorter tier when the fullest wording would not fit'`) uses a
    deliberately narrow `labelWidth: 90` to prove the degrade path itself.
- Re-ran the browser gate after the fallout fix: green, including at narrow width.

## Decisions and assumptions

| Item | Class | Evidence | Effect |
|---|---|---|---|
| `DataPoint.category` shape | Decision (this task, user-authorized) | CR-VT01 report's option (a); `research/00-decisions.md` decisions 8/10 re-read and found not violated (plain optional string, no DOM measurement, resolver still data-blind to values — only the point's own datum, same tier as `y`) | Public `packages/core` type gains one optional field. Backward compatible; no existing caller breaks. |
| `labelWidth` budget = `plot.width`, not `stage.width` | Repository-derived, verified via `funnelFrame()`'s own arithmetic | `x = plot.x + (plot.width - width) / 2` (vertical) / `x = plot.x` (horizontal) — both put every stage's label at the same horizontal position regardless of its own share | Using `stage.width` would have wrongly degraded low-share stages that actually had full-plot room; using `labelWidth` does not. |
| Text-fit tiers implemented in `packages/primitives`, not `packages/core` | Precedent | `Labels.tsx`/`CompactSeriesKey.tsx` already call `measureText()` (pure) at this layer, not inside `packages/core` | Consistent with existing seam; no new architectural pattern introduced. |
| Fixture `labelWidth: 600` for hand-authored renderer-test frames | Measured, not guessed | Full-tier "Details…" text measured 480.6px, zero-baseline full-tier text measured 538.95px at rank D — see scratch measurement below | 600 comfortably exceeds both, keeping pre-existing composition-wording assertions decoupled from the new degrade feature. |
